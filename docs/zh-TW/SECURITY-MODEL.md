# 安全模型：relay 看到什麼，組員能做什麼

把資料夾和 AI agent 透過一台伺服器分享給組員，安全嗎？這台伺服器（relay）只轉送加密後的資料，內容它讀不到，但它知道
誰在連線、從哪裡連、什麼時候連。加密擋不住你自己邀請進來的人：每個成員都讀得到檔案和每一段對話，有「可使用 agent」
角色的組員更是以你的身分在你的電腦上做事，沒有沙盒。smurg 還是原型，沒有經過外部稽核。
英文版：[English](../SECURITY-MODEL.md)。

## 東西放在哪裡

都在你的電腦上：檔案、agent 和終端機，以及放在 `~/.smurg` 裡的對話和工作區的金鑰。

## 加密了什麼

工作區裡傳遞的一切（檔案、對話、終端機畫面），都在你的電腦和每位組員的瀏覽器（或 CLI）之間端對端加密。

邀請連結的結尾是 `#k=…&s=…`：一個是工作區金鑰的指紋，組員的瀏覽器會核對它；另一個是讓人加入的密鑰。這個密鑰 relay
看不到。拿到連結的人，在連結過期或被撤銷之前都能加入，所以請用私訊傳（[分享](HOSTING.md#3-分享)）。

## relay 知道什麼

- **看得到**：每條連線是哪個 Google 帳號、從哪個 IP 位址連線、連到哪個工作區，以及每筆資料的大小和時間。
- **保存**：每個工作區的代碼和它的主人是哪個帳號；另外，`smurg login` 的登入請求和用來擋下猜代碼的次數紀錄，最多
  保存 10 分鐘。
- 用公用 relay 時，smurg 的維護者和 Cloudflare 可能知道這些（[詳細內容](HOSTING.md#21-公用-relay預設)）。你也可以
  [自己架設](HOSTING.md#22-其他-relay--relay)。

## 加密保護不了什麼

- **網頁版是 relay 提供的**：relay 如果送出被竄改過的網頁版，就讀得到瀏覽器解密的內容和瀏覽器的金鑰。
- **每個成員都看得到檔案，也能下載**（`.env` 也一樣），讀得到每一段對話，也看得到每個終端機的畫面：「旁觀」的成員和
  之後才加入的成員也一樣。不要分享放了機密的資料夾（[主人指南 §4](HOSTING.md#4-分享前必讀)）。
- **agent 都不在沙盒裡**：現在的 agent 是 Claude Code，用的是你的 Claude 帳號。個人訂閱只供你自己使用，
  [不供多人使用](HOSTING.md#4-分享前必讀)。除非你選擇要被問，agent 都以 Claude Code 的自動模式執行：由 Claude Code 決定
  哪些指令可以執行（agent 自己資料夾裡的簡單檔案指令直接執行，其他的先經過它的檢查），smurg 自己仍會在少數幾種指令前先問
  （[§5.2](HOSTING.md#52-agent-自己能做什麼什麼要先問)）；你自己的允許規則也適用
  （[§5.3](HOSTING.md#53-你自己的-claude-code允許規則mcp-伺服器專案設定claudemd)）；被允許的事是以你的身分執行的，而且
  組員的檔案裡可能藏著要 agent 照做的指示。
- **「可使用 agent」等於你的帳號**：有這個角色的組員可以在你的電腦上執行任何指令、讀你的家目錄、用你的 Claude
  帳號，這些 smurg 都沒有辦法限制。這個角色只給你完全信任的人（[§5.1](HOSTING.md#51-可使用-agent角色請先讀)）；
  其他組員請用「可編輯」（[角色](JOINING.md#2-角色可以做什麼)）。

## 驗證過什麼

smurg 是用照劇本回應的模型替身[驗證](HOSTING.md#108-驗證過什麼還沒驗證什麼)的，沒有用真正的 Claude 帳號。
加密（Noise 通訊協定）是 smurg 自己實作的，沒有經過外部稽核。
信任模型和已知的限制：[`docs/ARCHITECTURE.md`](../ARCHITECTURE.md#2-trust-model-in-one-page)（英文）的 §2 和
[§12](../ARCHITECTURE.md#12-known-limits-of-the-prototype)。

發現漏洞請私下回報，不要開公開的 issue：[`SECURITY.md`](../../SECURITY.md)（英文）。
