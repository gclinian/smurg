# 運作方式：團隊和 AI agent 的工作區

用 smurg，你（主人）從自己的電腦分享專案資料夾，組員用瀏覽器加入，每個人都即時看得到 agent 在做什麼，也讀得到每一段
對話。你和「可使用 agent」的成員傳訊息給 agent，「可編輯」的成員傳的是建議，agent 提出的選擇題由團隊投票。
英文版：[English](../HOW-IT-WORKS.md)。

## 三個部分

- **你的電腦**執行 `smurg host`。檔案和 agent 都留在這台電腦上，agent 也是以你的身分執行
  （[這代表什麼](#目前的狀態)）。
- **relay** 在你和組員之間轉送資料，但讀不到內容：資料是端對端加密的。不過它知道是哪個帳號在連線、從哪個 IP 位址連、
  什麼時候連（[relay 看得到什麼](HOSTING.md#21-公用-relay預設)）。
- **瀏覽器**是組員唯一需要的程式：用 Chrome 打開邀請連結，再用 Google 帳號登入。

## 好幾個人，同一個 agent

每個[角色](JOINING.md#2-角色可以做什麼)能對 agent 說什麼：

- **你，以及「可使用 agent」的成員**：可以傳訊息給任何 agent、開始工作、採用建議，也可以允許或拒絕 agent 請求執行的事。
- **「可編輯」的成員**：傳的訊息是建議，有人採用之後 agent 才會收到。他們也可以編輯檔案、檢視結果報告。
- **「旁觀」的成員**：只能看。

agent 被要求把需要決定的事用選擇題交給團隊。除了「旁觀」，每個人都可以投票，再由一個人送出答案：投票只是參考
（[選擇題與投票](JOINING.md#53-選擇題與投票)）。

## 從討論到合併

一個主題就是一個功能或一件工作（[每一步的說明](JOINING.md#6-主題從討論到看過結果)）：

1. **討論**：團隊和一個 agent 討論這個主題，agent 再寫出 spec。
2. **計畫**：agent 把 spec 變成由工作項目組成的計畫；這兩個檔案，「可編輯」以上的成員都可以編輯。
3. **工作**：每個工作項目有自己的 agent，在自己的 git worktree 裡工作（資料夾沒有 git 時，用 smurg 自己的版本紀錄）。預設的
   自動模式下，它在裡面改檔案、執行指令都不用先問：簡單的檔案指令直接執行，其他的在 Claude Code 的檢查允許後執行
   （[什麼要先問](HOSTING.md#52-agent-自己能做什麼什麼要先問)）。
4. **檢視**：做完的項目附有一份結果報告，寫明做了什麼、怎麼驗證的，以及每一個改過的檔案的 diff。有人讀過之後，把它
   標成已看過。
5. **合併**：看過不等於合併。只有你（主人）能合併，而且要先讀過
   diff（[合併](HOSTING.md#103-合併以及什麼在等它)）。

## 目前的狀態

- **agent 就是 Claude Code**：它以你的身分在你的電腦（macOS 或 Linux）上執行，沒有沙盒，用的是你的 Claude 帳號，替組員
  工作時也一樣。worktree 只是工作的位置，不是保護。只把「可使用 agent」給你完全信任的人
  （[分享前必讀](HOSTING.md#4-分享前必讀)）。
- **還是原型**：這個流程是用照劇本回應的模型替身驗證的，沒有用真正的 Claude 帳號，所以真正的模型在這個流程裡的表現
  還沒有驗證過（[驗證過什麼](HOSTING.md#108-驗證過什麼還沒驗證什麼)）。
