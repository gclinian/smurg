# 組員指南：加入別人分享的工作區

這份文件寫給**組員**：有同學用 smurg 把專案資料夾分享出來，傳了一個邀請連結給你。你不需要用過 smurg，也不需要用過
Claude Code。主人（分享資料夾的人）請看[主人指南](HOSTING.md)。這份指南的英文版：[English](../JOINING.md)。

先知道四件事：

- **所有檔案都在主人的電腦上**。你在瀏覽器裡看到、改到的，就是主人電腦上的那份檔案；存檔是自動的。
- **Claude Code** 是 AI 程式助手（以下叫 **agent**）：你用一般的句子告訴它要做什麼，它會讀檔案、改程式、執行指令。在
  smurg 裡，每個 agent 都在主人的電腦上、以主人的身分、用主人的 Claude 帳號執行，工作區裡的每個人都能即時看到它在
  做什麼。
- **工作是以主題來安排的。** 一個主題就是一個功能或一件工作。大家一起和 agent 討論，agent 會出選擇題讓團隊決定，再寫出
  spec；接著 agent 把 spec 變成一份由工作項目組成的計畫；每個工作項目由一個 agent 完成；最後由人閱讀每一份結果報告並
  標記為已看過（§6）。
- 你和主人電腦之間的連線是**端對端加密**的：中間轉送資料的伺服器（relay）看不到檔案內容、對話、終端機畫面或指令（它
  知道你用哪個帳號登入、從哪個 IP 連線）。

## 1. 用邀請連結加入

邀請連結長這樣：`https://<網站>/join/<工作區代碼>#k=…&s=…`。主人用 smurg 的公用 relay 時，`<網站>` 就是
app.smurg.ai（連結是 `https://app.smurg.ai/join/…`；https://smurg.ai 是 smurg 的介紹頁和使用說明，不能打開工作區）；主人
用 `--relay` 指定了其他 relay（例如他自己架設的）時，是那個 relay 的網址。`#` 後面那一段是**密鑰**，有了它就能加入
工作區：不要轉貼到群組或公開的地方，也不要只複製 `#` 前面的部分。

1. 用瀏覽器打開連結（電腦上的 Chrome 最穩；Safari、Firefox 還沒測試過）。
2. 登入：按「**使用 Google 登入**」，用你的 Google 帳號登入（其他 relay 可能也有「使用 GitHub 登入」，出現哪些
   按鈕由架設 relay 的人決定）。smurg 只用登入確認你是誰，不會取得你的程式碼；你**不需要** Claude 帳號或 API key。
   relay 知道你用哪個帳號、從哪個 IP 連線（[主人指南](HOSTING.md) §2.1）。
3. 畫面會問「要加入這個工作區嗎？」，列出工作區代碼和你登入的身分。確定是主人給你的連結，就按「**加入**」。
   加入後，主人會看到你的名稱、帳號和裝置名稱。
4. 進入工作區。左邊是你的收件夾和依主題分組的 session 清單；右邊最多可以並排四欄：agent 的對話、spec、計畫、結果報告
   （§3）。最上面一排顯示主人是誰、連線狀態（「已連線」）、你的角色，以及在「session」（這個畫面）和「手寫 code 模式」
   （檔案樹和編輯器，§4）之間切換的開關。

介面有英文和繁體中文：一開始依瀏覽器的語言，之後可以用畫面上的語言選單切換（登入頁和加入頁上也有）。每個人看到的是
自己選的語言；這份指南引用的是繁體中文介面的文字。agent 的名稱（例如 `Claude (Amy)`）、主題和工作項目的名稱，以及別人
或 agent 寫的文字不會翻譯。

之後直接打開工作區就好（首頁的「最近開啟的工作區」），不需要再用邀請連結：這個瀏覽器已經記住了主人電腦的金鑰。
私密瀏覽視窗記不住，關掉之後要新的邀請連結才能再加入。

加入之後，工作區裡的所有東西你都讀得到，包括你來之前和 agent 的每一段對話。

**要不要核對「金鑰指紋」？** 主人分享時，在自己的電腦上執行 `smurg status` 可以看到一組 daemon 金鑰指紋。第一次加入時，
你可以用其他管道（當面、電話）請主人唸給你聽。如果看到「**安全警告：已拒絕連線**」或「主人的電腦金鑰和之前不同」，
**先不要繼續**：可能有人在冒充主人。也可能是主人換了工作區的金鑰（例如收回某位組員的「可使用 agent」之後重新分享，
或重新安裝了 smurg）。請用其他管道（當面、電話）問主人：

- 主人說他**沒有**換過：不要繼續，按「取消」，告訴主人。
- 主人說他換過：請他給你新的邀請連結，並唸出他用 `smurg status` 看到的新 daemon 金鑰指紋。用新連結時會看到「主人的
  電腦金鑰和之前不同」：確認是主人剛給你的連結之後，按「我已向主人確認，使用新的連結」。用終端機加入的話，`smurg attach`
  會印出「邀請連結的金鑰指紋」：和主人唸的一樣才輸入 `y`（見 §10）。

其他你可能看到的畫面：

| 看到 | 意思 |
|---|---|
| 「邀請連結無法使用」 | 連結過期、次數用完或被主人撤銷：請主人給你新的連結。還有一種情況：你已經是成員，而這個連結的角色和你的不一樣（主人給組員的連結通常是「可編輯」的連結）。如果這個瀏覽器之前就加入過，只是因為「主人的電腦金鑰和之前不同」才需要連結，新的金鑰其實已經記下來了：不用連結，再打開一次工作區就好（首頁的「最近開啟的工作區」）。如果是新的裝置，請主人給你符合你角色的連結。 |
| 「這個瀏覽器已經用另一個帳號加入過」 | 一個瀏覽器設定檔在一個工作區裡只能是一個人：第一次加入時，這個瀏覽器就綁定了當時登入的帳號。請登出後改用原本的帳號登入；要用別的帳號，請換一個瀏覽器設定檔或無痕視窗再開邀請連結。 |
| 「你已被移出工作區」 | 主人把你移出了工作區。要再加入需要主人給你新的連結。 |
| 「角色已變更」 | 主人改了你的角色，畫面會自動重新連線並套用新的權限。 |
| 「無法連上伺服器」 | 你自己的網路（或 relay）有問題，不是主人離線。用 smurg 的公用 relay 時，也可能是今天所有人共用的免費用量用完了，UTC 0 點（台灣時間早上 8 點）後恢復（[主人指南](HOSTING.md) §2.1）。 |
| 「主人已離線」 | 見 [§8](#8主人已離線是什麼意思)。 |

## 2. 角色：可以做什麼

主人在邀請連結上決定你的角色，之後也可以在主人控制台改。

| | 旁觀 | 可編輯 | 可使用 agent |
|---|:-:|:-:|:-:|
| 看檔案、下載檔案或資料夾、讀每一段對話、spec、計畫和結果報告、看每個終端機的畫面 | ✅ | ✅ | ✅ |
| 被其他成員提及（會出現在你的收件夾） | ✅ | ✅ | ✅ |
| 編輯、新增、重新命名、刪除、上傳檔案；編輯主題的 spec 和計畫 | ❌ | ✅ | ✅ |
| 對 agent 的選擇題投票和留言；提及其他人 | ❌ | ✅ | ✅ |
| 對 agent 提出建議（要有「可使用 agent」的人採用，agent 才會收到） | ❌ | ✅ | ✅ |
| 當 session 或工作項目的負責人；檢視結果報告 | ❌ | ✅ | ✅ |
| 開始主題、請 agent 產生計畫、開始工作項目、開 agent session 和終端機（**以主人的身分執行**） | ❌ | ❌ | ✅ |
| 傳訊息給任何 agent、停止它、用自己的話回答 agent 的選擇題 | ❌ | ❌ | ✅ |
| 允許或拒絕 agent 請求執行的事；採用或不採用建議 | ❌ | ❌ | ✅ |
| 在**任何**終端機 session 裡直接輸入 | ❌ | ❌ | ✅ |
| 請主人合併 worktree | ❌ | ❌ | ✅ |

只有主人能做的事：邀請成員、改角色、踢人、看操作紀錄、強制釋放檔案鎖、合併 worktree、允許會動到專案以外的請求、確認
資料夾的 Claude Code 設定，以及刪除主題。

**「可使用 agent」是什麼意思**：你開始的 agent 和你開的終端機，在主人的電腦上**以主人的身分**執行，沒有沙盒：agent 用的是
主人的 Claude Code 登入（用量和費用算在主人身上），你允許它執行的事，可以做主人的帳號能做的任何事。所以主人只會把這個
角色給完全信任的人。你不需要、也不能用自己的 Claude 帳號或 API key。

有幾類檔案組員**看不到**：所有 `.git` 資料夾、`.envrc`、smurg 自己的 `.smurg/`，以及主人個人的 Claude Code 設定
（`.claude/settings.local.json`、`CLAUDE.local.md`）。有幾類檔案組員**看得到但不能改**（檔案樹上會標示「只有主人可以修改
這個檔案」）：`.claude/`、`.mcp.json` 和每一個 `CLAUDE.md`（主人的 Claude Code 會把它們當成設定和指示來讀）、`.vscode/`、
`.idea/`。主人使用資料夾的 Claude Code 設定期間，那些設定會執行的腳本，組員也不能改；檔案樹上不會標示這些腳本，修改時
會被拒絕。資料夾裡只要有只有主人能改的檔案，或有組員看不到的檔案，不論在第幾層，組員都不能重新命名或刪除這個資料夾：那
等於把檔案一起移走。這可能是你想不到的資料夾，例如 `node_modules`，只要裡面有某個套件附了 `CLAUDE.md` 或 `.vscode`
資料夾。你會看到「只有主人可以修改這個路徑」；請主人來做。
除此之外，資料夾裡的每個檔案，每個成員都看得到（包括 `.env` 之類的設定檔）。這些限制適用於人在網頁和 CLI 裡的
操作。agent 也被擋在那些看不到的檔案之外，但有人允許的指令和任何終端機都是以主人的身分執行的，不受這些限制。

## 3. 主畫面：收件夾、session 與欄

你進來時看到的畫面就是 session 畫面（最上面開關的「session」那一邊）。

**收件夾**（左上）放的是等你處理的事，分成兩組：

- 「agent 在等你」：有 agent（或整份計畫）停下來，等人處理。包括由你決定的 agent 選擇題、還開著的投票、你可以回答的
  權限請求，以及停下來需要有人處理的工作（沒寫報告就停下的 agent、失敗或沒有開始的工作項目、重新啟動之後暫停的計畫）。
- 「等你看的」：你負責的 session 收到的建議、等你檢視的結果報告、可以合併的變更（主人）、提到你的訊息，以及你自己提出的
  建議後來怎麼了。

收件夾顯示兩個數字：有幾項在等、有幾項待看。你在手寫 code 模式時，開關的「session」那一邊也會顯示這兩個數字；瀏覽器
分頁的標題只顯示有幾項在等。關於它，你需要知道：

- **項目是一件在等的事，不是一則訊息。** 那件事處理完，項目就會離開，不論是誰處理的，所有人的收件夾同時更新。你不能自己
  把它關掉。只有提及，以及你自己的建議的結果，可以關掉；這兩種一打開也會離開收件夾。打開其他項目只會讓它不再是粗體。
- **會進誰的收件夾**：agent 的選擇題進決定它的人的收件夾（§5.3）；權限請求和建議，在 session 的負責人可以回答時進他的
  收件夾，否則進主人和每一位「可使用 agent」成員的收件夾；結果報告進檢視它的人的收件夾（§6）。該回答選擇題或權限請求
  的人沒有處理時（預設 5 分鐘，或他已經離線 1 分鐘），它也會出現在主人和「可使用 agent」成員的收件夾，他們可以代為
  處理。結果報告要等六倍的時間（預設 30 分鐘）才會這樣。建議則留在原本的收件夾；主人和每一位「可使用 agent」的成員
  仍然可以在它的卡片上採用。
- 「旁觀」的成員只會收到提及，收件夾裡會這樣寫：目前沒有等你處理的事。「旁觀」的成員在這裡只會收到提及。
- 「agent 在等你」裡有新項目、而它的 session 不在你的畫面上時，也會跳出一則附有「開啟」的簡短通知。

**session 清單**（在收件夾下面）依主題分組。每個主題有固定的幾列：「討論」（大家共用的那個 session）、「spec」、「計畫」，
計畫出來之後每個工作項目各有一列。不屬於任何主題的 session 在「未分主題」這一組；終端機 session 有終端機的圖示。清單
上方的「新增」可以開始主題、開單一的 agent session 或終端機（「可使用 agent」和主人），篩選可以選「全部」、「我的」或
「等待中」。粗體的那一列，表示從你上次把它放在畫面上之後，那裡發生了事情。

每個 session 會顯示它在做什麼：

| 狀態 | 意思 |
|---|---|
| 「執行中」 | agent 正在工作。 |
| 「等待回答」 | agent 提出了選擇題，在等答案。需要有人處理。 |
| 「等待許可」 | agent 請求執行某件事，在等待。需要有人處理。 |
| 「沒寫報告就停下了」 | 工作項目的 agent 還沒寫結果報告就停下了。需要有人看一下。 |
| 「待命」 | agent 做完了這一輪，在等下一則訊息。討論大部分時間都是這個狀態。 |
| 「完成」 | 工作項目做完了，結果報告也寫好了。 |
| 「失敗」 | agent 的程序因錯誤結束。可以再試一次。 |
| 「已結束」 | session 被人結束了，或自己結束：工作項目合併並看過之後，它的 session 會結束；主題封存時，主題的 session 也會結束。它的對話仍然讀得到（不屬於主題的 session：保留 30 天）。 |

**欄**（右邊）是你自己的畫面；別人看不到你開了什麼。

- 點一下清單裡的一列或收件夾的項目，就會把它開成一欄。「在旁邊開啟」（那一列上的按鈕、Shift+點擊或 Shift+Enter）會在
  你正在讀的那一欄旁邊多開一欄，而不是取代它。
- 最多可以並排四欄，分隔線可以拖曳。第五欄會被拒絕：
  「已經開了四欄，請先關閉一欄。」
  視窗太窄、放不下全部的欄時，放不下的欄可以用欄位邊緣的按鈕切換過去（`還有 1 欄`）。
- 「釘選這一欄」可以讓一欄不被取代；正在執行的主題，它的計畫會自己釘選。
- 關掉一欄不會結束 session。
- 左邊可以收起來：收件夾和 session 清單可以各自摺疊，整個左欄也可以縮成一條窄邊，上面只顯示一個數字：有幾項在等；
  沒有東西在等時，顯示有幾項待看。

## 4. 手寫 code 模式：一起編輯檔案

最上面一排的「手寫 code 模式」會切換到檔案樹和編輯器；「session」切回來。兩邊都會保留原來的狀態：你回來時，之前開的欄
都還在。你在手寫 code 模式時，收件夾的數字仍然顯示在開關上。

- 在左邊的檔案樹**點一下檔案**就會在編輯器打開；在檔案或資料夾上**按右鍵**可以新增、重新命名、刪除、下載（資料夾會打包成
  zip）。檔案樹上方的按鈕可以新增檔案、資料夾或上傳。
- **大家可以同時打字**，每個人的游標會用不同顏色和名字顯示；agent 改檔案時會用它自己的名稱顯示，例如名為 Cart API 的
  工作項目，它的 agent 是 `Claude (Cart API)`。
- **不用按儲存**：停下來一下就會自動存到主人的電腦（編輯器會顯示「已自動儲存」）。一直顯示「尚未儲存：正在等待主人電腦
  回應」的話，通常是連線有問題。
- **上傳**：把檔案或整個資料夾拖到左邊的檔案樹。大檔案也可以，斷線後會從中斷的地方繼續；主人的磁碟空間不夠時，上傳在
  開始前就會被拒絕並說明原因。一次上傳最多可以有 10,000 個資料夾，檔案所在的每一層資料夾都算；超過的話，在建立任何東西
  之前就會被拒絕（「請分批上傳」）。進度在下方的「傳輸」。
- 太大（超過 5 MB）、二進位或不是 UTF-8 的檔案不能在編輯器裡打開，可以下載後用自己的程式開啟。
- **smurg 不接受的名稱。** 檔案或資料夾的名稱裡有控制字元、反斜線、會改變文字方向的字元，或是同一個字母上疊了超過 30 個
  附加符號（重音、聲調這類組合字元）時，它不會列出來，也不能開啟、建立或上傳。沒有任何語言的字需要疊這麼多。agent 和
  終端機是以主人的身分執行的，它們看這樣的檔案和其他檔案沒有兩樣。
- **編輯器旁的 session**：手寫 code 模式的右邊會顯示你選的一個 agent session，和 session 畫面裡是同一段對話。agent 讀過
  或改過的檔案，在對話裡有「在編輯器開啟」；它會帶你到這裡並打開那個檔案，「回到這個 session」則會回去。
- 在編輯器裡**選取一段程式碼**，按「送到 agent」，可以把它連同檔名和行號放進要給 agent 的訊息（你的角色是「可編輯」時
  會是一則建議，見 §5）。
- 下方的「活動」會即時列出誰（或哪個 agent）新增、修改、刪除、上傳了哪個檔案；點一下就能打開那個檔案。檔案樹上也會標示
  「最近由 … 修改」。顯示為「**外部程式**」的，是 smurg 無法確定是誰的修改（例如主人用別的程式改的）。下方的「終端機」
  放的是一般的終端機 session（§5.5）。
- 檔案樹上方的「檢視的工作區」可以在主工作區和各個 worktree 之間切換（§7）。

### 4.1 檔案鎖的提示是什麼意思

smurg 用檔案鎖避免人和 agent 互相覆蓋。你會在編輯器上方或檔案樹上看到這些提示；在欄裡編輯 spec 或計畫時也會看到：

| 提示 | 意思 | 你可以做什麼 |
|---|---|---|
| 「你正在編輯這個檔案，agent 暫時不能修改它。」 | 你一開始打字就拿到了這個檔案的**編輯鎖**：所有 agent 都不能改它（agent 會收到一句英文："This file is being edited by <你的名字>. Work on other files first, or try again later."）。其他人仍然可以和你一起打字。 | 照常編輯。停下來 30 秒（主人可以調整）沒打字、或關掉這個檔案，鎖就會放掉。想讓 agent 馬上改，按「**讓 agent 先改**」（你再打字時會重新拿到鎖）。 |
| 「你和 Amy 正在編輯這個檔案（共用編輯鎖）…」 / 「Amy 正在編輯這個檔案…」 | 幾個人共用同一把編輯鎖，agent 暫時不能改。 | 同上。 |
| 「Claude (Amy) 正在修改，暫時無法輸入」 | 這個 agent 正在改這個檔案：編輯器暫時**唯讀**，其他 agent 也不能改。 | 等一下：改完（預設最多 60 秒）就會自動恢復可以輸入。這段時間打的字不會被接受。 |
| 檔案樹上的「… 修改中」「… 編輯中」 | 同上兩種鎖。 | |
| 「這個檔案對你是唯讀的」 | 你的角色不能編輯、這是只有主人能改的檔案，或是 worktree 裡唯讀的資料夾（共享資料夾，或工作項目的 worktree 裡主題的 `specs/` 資料夾）。 | |
| 「這個檔案已被 … 刪除」 / 「已被移到 …」 | 有人刪除或移動了你正開著的檔案，這個分頁不能再存檔。 | 「用這些內容重新建立」或「開啟新位置」。 |

**衝突**：程式也可能不經過檔案鎖直接改檔案（主人自己的編輯器，或 agent 被允許執行的指令，例如 `sed`、格式化工具、
`git checkout`）。如果它改到了有人正在編輯的地方，smurg 會**保留人正在打的內容**，把另一個版本放到手寫 code 模式下方的
「**衝突**」面板，並通知雙方。在衝突面板可以左右對照兩邊的內容，選「保留編輯中的內容」，或「套用這個版本…」用另一方的
完整版本取代整個檔案。還沒處理的衝突會以數字顯示在最上面一排的「手寫 code 模式」上。

## 5. 和 agent 對話：訊息、建議、選擇題與投票

agent session 是一段對話，每個人都讀得到全部內容，包括你打開之前發生的事。你會看到每個人的訊息（附名稱和角色）、agent
的回答，以及 agent 做的每一件事各一行（「讀取」「編輯」「建立」「執行」「搜尋」），可以展開來看變更或輸出。等人處理的事是
對話裡的卡片：選擇題、權限請求、建議。

對話上方有一排資訊，顯示誰負責這個 session（「負責人：Ian」或
「負責人：無」）、agent 在哪裡工作（主工作區或某個 worktree），以及它不用先問就能做什麼（例如「執行指令前先問」；主題的
討論顯示「可讀程式碼，只能寫 spec 和計畫」）。訊息輸入框上面那一行會說明 agent 正在做什麼，或它在等什麼
（例如「Claude 待命中。」）。

**agent 或成員寫的連結。** 連結會在新分頁開啟；把滑鼠停在連結上、或用鍵盤移到它上面，就會顯示它連到哪裡。圖片一律不會
載入：圖片會變成連到它的連結。連結的文字寫的是另一個地方、和它實際連到的地方不同時，smurg 不會把這些文字畫成連結：它把
文字當成一般文字寫出來，後面再接上真正的目的地當作連結：`github.com (https://evil.example/)`。文字裡帶句點的名稱只要含有
英文字母以外的字母（知名名稱裡長得很像的字母、帶變音符號的字母），或句點旁邊有看不見的字元，不論連結連到哪裡，smurg 也
會這樣做。這是輔助，不是保證。smurg 會把文字當成一個地方來讀的情況有三種：它是網址、是後面帶有路徑的名稱，或是結尾屬於
大約五十個常見結尾（`.com`、`.org`、`.io`、`.tw` …）的單獨名稱。下面這些會畫成一般的連結，目的地只有用滑鼠和鍵盤才看得到：

- 其他結尾的單獨名稱（`amazon.in`、`bbc.it`、`github.lol`）：從拼法分不出它和 `README.md` 這類檔名；
- 名稱裡的句點其實只是長得像句點的符號（置中的點、其他文字系統的數字零），或句點前面有一個畫出來幾乎沒有寬度的字元；
- 躲在會反轉文字方向的字元後面、倒過來寫的名稱。訊息裡的這種字元會被 smurg 移除，所以這只會出現在 spec 或其他檔案裡；
- 文字剛好就是連結所連到的檔案的名稱，不論它用什麼字母寫（這樣 `résumé.pdf` 才能連到那個檔案）。結尾比較少見、字母又
  長得很像的名稱，只要連結自己的網址也以它結尾，就會這樣通過。

所以點連結之前，請先看它連到哪裡。

**來不及排版的文字。** agent 和人寫的內容會排版後顯示（標題、清單、程式碼）。太長、層次太深，或排版要花太久的文字，會
照原樣顯示，上方有一行說明：「以原文顯示：這段文字太長或層次太深，無法排版。」spec 是一段一段排版的：時間用完時正在處理
的那一段照原樣顯示，其餘照常排版；時間第二次用完的話，整份 spec 都照原樣顯示。一次來了非常多段文字時，排不到的會先照
原樣顯示一下（沒有那行說明），等瀏覽器有空就排版，畫面上看得到的優先。

### 5.1 訊息（主人與「可使用 agent」）

- 在輸入框（「傳訊息給 Claude」）裡寫好，按 Enter；Shift+Enter 換行。agent 正在工作時，它會在下一步讀到你的訊息。輸入
  `@` 可以提及某位成員。
- agent 會知道每一則訊息是誰寫的（你的名稱和角色）。smurg 自己告訴 agent 的話一律是英文，不論你用哪種語言；你可以用任何
  語言寫給 agent。
- 「停止」會結束 agent 現在正在做的事；session 仍然開著。要永久結束一個 session，在那一欄的選單裡（「結束 session…」），
  只有主人，以及開這個 session 或負責它的「可使用 agent」成員有這一項；agent 的指令留著在跑的程式（開發伺服器、監看檔案
  的程式）也會一起結束。主題的討論不能結束，只能重新開始（§6）。
- 訊息會照你寫的樣子送到 agent 手上。Claude Code 自己的斜線指令不能用：以 `/` 開頭的訊息會被當成一般文字。`@路徑` 也
  不會被換成檔案的內容：想讓 agent 看某個檔案，寫出它的路徑，它會用自己的工具去讀（需要許可時會先問）。這個版本的
  agent 不會啟動 subagent。
- 還沒送出的文字會留在輸入框裡。它依 session 存在這個瀏覽器裡，直到你送出、離開工作區、登出或被移出為止。
- **請記得**：agent 是用主人的電腦和主人的帳號工作的，用掉的是主人的 Claude 用量。只請它做主人同意的事，也絕對不要在
  對話裡貼上密碼或 API key：每個成員都讀得到。

### 5.2 建議（「可編輯」）

- 身為「可編輯」的成員，你用的是同一個輸入框；它會顯示「向 Claude 提出建議」，按鈕是「送出建議」。下面那一行會說明誰會
  收到，例如「會以建議的形式送給 Ian，採用之後才會送給 agent。」
- 你的建議會以卡片出現在對話裡（「Amy 的建議」），也會出現在 session 負責人的收件夾，或主人和「可使用 agent」成員的
  收件夾。他們可以選「採用」、「修改後採用」或「不採用」（可以附上原因）。「有人採用之後，它才會送給 agent。」smurg
  不會自動採用。
- 被採用之後，它會變成對話裡你的一則訊息，標示「建議，由 Ian 採用」，agent 讀到的就是畫面上顯示的那段文字。不被採用，或
  修改後才採用時，卡片會這樣顯示，你的收件夾也會收到一則說明。
- 在有人決定之前，你可以修改（「編輯」）或收回（「撤回」）。同一個 session 裡，你最多可以有 20 則建議在等待。
- 看不見的字元會在儲存和顯示之前從你寫的內容裡移除
  （「已移除看不見的字元」）：別人採用的內容，就是 agent 收到的內容。同一個字母上疊了超過 30 個附加符號時，也會用同樣的
  方式只留下前 30 個；人在對話裡寫的每一種文字都是這樣（訊息、建議、留言、回答、附註）。
- 其他會把文字送給 agent 的輸入框也一樣，例如 spec 上的「請 agent 修改」和結果報告下方的輸入框：「可編輯」的成員在那裡
  寫的也是建議。
- 建議只能送給 agent session，不能送給終端機。「旁觀」的成員不能提出建議：
  他們可以觀看 session，但不能傳訊息、提出建議或投票。

### 5.3 選擇題與投票

agent 被要求把需要決定的事用選擇題交給團隊。選擇題是一張卡片
（「Claude 的選擇題」），agent 會等到有答案為止。

- **除了「旁觀」，每個人都可以投票**（「你的投票」）。大家即時看得到彼此的選擇，在答案送出之前都可以改。得票最多的選項
  會標示「領先」。「其他」可以投給你用自己的話寫的答案。
- **留言**在選項下面；`@名稱` 可以提及某個人。「留言是給團隊看的，Claude 不會讀。」
- **由一個人決定**，卡片上會寫是誰：session 的負責人；沒有指派負責人時，是開 session 或按開始的人（主題的討論：建立主題
  的人，或重新開始討論的人）；那個人不在了就是主人。投票只是參考：決定的人點一個選項再按「送出答案」，和投票結果不同也可以
  （「你現在就可以送出；投票只是參考。」）。票數相同時不會預先選好：
  「票數相同，請你自己選擇答案。」
- **agent 收到的內容**：答案，以及投票的結果。不包括留言，也不包括其他人自己寫的答案。決定的人如果有「可使用 agent」，
  可以加上「給 Claude 的備註（選填）」，也可以用「加到備註」把某一則留言放進去。由「可編輯」的成員決定時，只能從 agent
  給的選項裡選；要用自己的話回答，需要有「可使用 agent」的人（「請他們送出」）。
- 沒有指派負責人的 session（主題的討論就是，除非有人被指派為它的負責人）裡有選擇題開著時，它會出現在每一位還沒投票的
  人的收件夾。決定的人和主人可以按
  「提醒還沒投票的人」。
- **決定的人沒有回答**超過等待時間（預設 5 分鐘），或他已經離線 1 分鐘，主人和「可使用 agent」的成員可以代為送出
  （「代 Ian 送出」）；對話會記下來。主人隨時都可以送出。
- agent 可以在一張卡片裡問好幾題；每一題有自己的投票，一個按鈕一次送出全部。回答過的卡片會摺成幾行：每一題的答案、
  誰送出的、給 agent 的備註（「顯示投票和留言」可以展開其餘內容），所以一段討論裡做過的決定讀起來就像一份清單。

### 5.4 權限請求

在自己的 worktree 以外的地方，以及幾乎所有的指令，agent 都要先問。卡片
（「Claude 請求許可執行指令」）會顯示完整的指令，以及它會在哪裡執行。

- 主人和「可使用 agent」的成員可以回答：「允許一次」、「一律允許這類」或「拒絕」（可以附上一行，告訴 agent 改做什麼）。
  「可編輯」和「旁觀」的成員看得到請求，以及它在等誰。
- 如果你可以回答：先讀過指令。你允許的事會以主人的身分在主人的電腦上執行。請求的內容不會有任何部分被藏起來：看不見的
  字元會寫成看得見的記號，很長的指令或 diff 會放在可以捲動的方框裡。卡片會寫出這樣的方框總共有幾行，而且要把它捲到最後
  才能允許：把要求的內容捲到最後，才能按「允許」。
- 「一律允許這類」只對範圍很窄的幾類指令提供，可以選「在這個 session」或
  「在這個主題的所有 session」；agent 改了指令會執行的檔案之後，同一類指令也包含在內。由好幾個指令組成的指令
  （`pnpm test && git push`）不會提供：一個類型指的是一個指令。
- 有些請求會顯示「只有主人可以允許：它會動到共用專案以外的地方。」
- 資料夾的 Claude Code 設定會執行腳本時，agent 的 shell 指令只要可能改到那些腳本，smurg 自己就會先問；在 agent 自己的
  worktree 裡也一樣，不論已經一律允許了什麼。卡片上平常寫 Claude Code 理由的地方，會用你的語言寫出 smurg 的理由；指令會
  寫到腳本所在的位置時，只有主人可以允許。
- 先回答的人算數；之後卡片會顯示是誰允許或拒絕的。

### 5.5 終端機 session

一般的終端機是主人電腦上的一個 shell，用來手動執行測試、建置和其他指令。主人和「可使用 agent」的成員可以用 session
清單的「新增」開一個（「終端機」），也可以在任何終端機 session 裡輸入；「可編輯」和「旁觀」的成員只能看
（會標示「只能觀看」）。終端機和其他 session
一樣會開成一欄，在手寫 code 模式裡則在下方的「終端機」。在那裡輸入的每一行都是以主人的身分執行的：不要貼上密碼。
「在自己的終端機接上」會列出它的 `smurg attach` 指令（§10）。

## 6. 主題：從討論到看過結果

一個主題把一個功能或一件工作，從第一段對話帶到有人讀過、理解過的成果。每一步都是 session 清單裡這個主題的一列。

1. **新增主題**（主人與「可使用 agent」）：「新增主題」會問名稱，以及（想寫的話）你想做什麼。它會說明自己做的事：
   「開始討論」會在主人的電腦上、用主人的 Claude 帳號開一個 agent，它可以讀程式碼，只能寫這個主題的資料夾（專案裡的
   `specs/<資料夾>/`）。
2. **討論**：每個主題有一個大家共用的 session。除了「旁觀」，每個人都可以和 agent 對話（「可編輯」的成員透過建議，
   §5.2）；agent 用卡片提出選擇題，除了「旁觀」的人都可以投票（§5.3）。團隊覺得說得夠多了，主人或「可使用 agent」的
   成員可以按「現在就寫 spec」。
3. **spec**：agent 在主題的資料夾裡寫出 `SPEC.md`，並在討論裡告訴大家（「開啟 spec」）。在 spec 那一欄，你可以閱讀，
   也可以切換成編輯，和其他人一起直接改（檔案鎖和 §4.1 一樣：有人在打字時，agent 會等）。「請 agent 修改」會把你想改的
   地方送到討論裡，大家都看得到，agent 也可能先提出新的選擇題。在一份很大、又有些段落排版要花太久的 spec 裡（§5），最初
   的幾下按鍵可能每一下都要將近一秒，直到這些段落都被擱到一邊為止。
4. **計畫**：「產生計畫」（主人與「可使用 agent」）會請 agent 寫出 `PLAN.md`：一份**工作項目**的清單，每一項有標題、說明，
   以及它要等哪些項目。smurg 會檢查格式；讀不出工作項目時，計畫會顯示是哪一行有問題。之後 spec 改了，計畫會顯示出來，
   並提供「更新計畫」。
5. **誰負責**：agent 會在目前在場、「可使用 agent」的成員之中，建議誰照顧哪個工作項目，沒建議到的由 smurg 補上；
   「重新建議」會重新算一次。主人和「可使用 agent」的成員可以一項一項改，或選「不指派：大家一起看」；「可編輯」和
   「旁觀」的成員只能看誰負責。項目的負責人會在收件夾收到這個項目的 agent
   提出的選擇題、權限請求和結果報告。當負責人不會多出權限：「可編輯」的成員當負責人時，可以在 agent 給的選項裡決定
   選擇題、檢視報告，但指令仍然要由「可使用 agent」的成員允許。
6. **開始**（主人與「可使用 agent」）：真正執行之前，對話框會列出按下開始之後會發生的事：哪些項目現在開始、哪些要等
   其他項目、誰負責、上次開始之後誰手動編輯過 spec 和計畫，以及 smurg 會把這兩個檔案提交到主人的儲存庫。要開始，分享的
   資料夾必須是 git 儲存庫。
7. **執行**：每個開始的工作項目都是一個獨立的 agent session，在自己的 worktree 裡（§7），也是這個主題的一列。它的 agent
   在 worktree 裡改檔案不用先問，執行指令前會先問（§5.4）。計畫那一欄是總覽：什麼在執行、什麼在等人、什麼在等合併。
   要等其他項目的工作項目，會在那些項目合併之後自己開始，而且只有在 spec 和計畫仍然是按開始時確認過的內容時才會開始；
   如果它們改了，這個項目會等有人看過變更，再按「重新開始」。
8. **結果報告**：工作項目做完時，它的 agent 會寫一份有固定段落的報告：「做了什麼」、
   「為什麼這樣做」、「怎麼驗證的」（每一項檢查不是通過，就是未驗證）、
   「要注意什麼」和「變更」（每一個改過的檔案和它的 diff）。報告也會寫這份工作是怎麼結束的：
   「完成」、「部分完成」或「受阻」。在報告下面，你可以追問結果，或說要改什麼
   （「追問這個結果，或告訴 Claude 要改什麼」）；問題會送到這個項目的 session，回答在兩邊都看得到。項目完成（合併並且
   看過）之後就沒有這個輸入框了：
   「這個項目已經合併，它的 session 也結束了。請到討論裡提問。」
9. **檢視**：「我已看過」是給項目的負責人按的；沒有指派負責人時，除了「旁觀」，任何人都可以按，一個人按一次就算數。
   它的意思是：我讀了報告，也理解這次變更。報告寫的是「部分完成」或「受阻」時，會再跟你確認一次才算數
   （「標成已看過」）。agent 之後如果改了報告，會再請你看一次。
10. **合併**：看過不等於合併。看過的項目，它的變更會自己進到主人的收件夾
    （「已看過，可以合併」），主人讀過 diff 之後再把它合併到主工作區（§7）。
11. **主題完成**：每個工作項目都看過之後，主題就是「已完成」。「封存主題」可以把它收起來；它的檔案留在專案裡，對話也
    仍然讀得到（「顯示已封存的主題」）。

有東西停下來時，畫面上會顯示，也會有人在收件夾收到：

- 「沒寫報告就停下了」：agent 沒有寫報告就結束了這一輪，即使 smurg 又請過它一次。
  「繼續」會請它接著做。原因是別的時候，計畫和收件夾會寫出來：有人把 agent 停止了、smurg 重新啟動過，或發生了錯誤。
  其中一種錯誤是 smurg 沒辦法把這個項目的變更和報告一起記下來（例如有人一直在 worktree 裡打字）；對話裡會說明，agent 的
  下一輪結束時報告就會出現。
- 「失敗」：agent 的程序因錯誤結束。「再試一次」會接續同一段對話。連續三次啟動失敗之後，只有主人可以再試。
- 主人的 Claude 帳號用量用完了，或主人電腦上的 Claude Code 登出了：session 會這樣顯示並等待；只有主人能處理。
- 主人的 smurg 重新啟動之後，什麼都不會自己執行（§8）。
- 討論變得很長時，會提供「開始新的對話」：一段從目前的 spec 和計畫開始的新討論。之前那一段會留在清單裡，叫
  「先前的討論」。

agent 能不能照這個流程走，要看模型。smurg 會自己檢查計畫和報告的格式並請 agent 修正，也會把停下來的工作放進收件夾；
但這個版本的流程是用照劇本回應的模型替身測試的，沒有用真正的 Claude 帳號，所以可能有不順的地方，哪一步行不通時請告訴
主人。

## 7. worktree 與合併請求

worktree 是專案在主人電腦上的另一份獨立工作副本，有自己的分支。agent 在裡面改檔案，就不會弄亂大家共用的主工作區。
worktree 只是工作的位置，不是限制：在裡面執行的東西一樣是以主人的身分執行。

- **每個工作項目有自己的 worktree**；smurg 在項目開始時建立它（要等其他項目的，在那些項目合併之後），項目合併並看過
  之後，等裡面沒有還沒合併的東西，就移除它。worktree 裡還有任何一次合併都沒有帶走的變更時（合併之後追問出來的修改、
  最後一份報告之後才做的修改），這個項目會留著它的 session 和 worktree。不屬於主題的單一 agent session 也可以在 worktree
  裡工作，或在主工作區裡工作。
- 手寫 code 模式裡，檔案樹上方的「檢視的工作區」可以切換看主工作區或任何一個 worktree。可以編輯的人也可以直接在 worktree
  裡改程式（一樣有檔案鎖）；結果報告會寫出哪些檔案也被人手動改過、是誰改的（重新命名、移動或刪除資料夾，算是改了它底下
  每一個有變更的檔案）。在工作項目的 worktree 裡，主題的 `specs/`
  資料夾對每個人都是唯讀的：裡面是 agent 開始時依據的 spec 和計畫，以及 agent 的報告。
- 主人指定的**共享資料夾**（例如不在 git 裡的 `data/`）會以連結的方式放進每個 worktree：在網頁裡它是唯讀的；agent 在
  worktree 裡寫進這個資料夾的話，改的就是主工作區裡的那一份。
- **工作項目的變更在它的結果報告裡看**：每個檔案和它的 diff，合起來是一次變更。組員看不到的檔案（§2）在那裡只列出
  檔名，不顯示內容。
- **合併由主人決定。** 看過的報告，它的變更會自己進到主人的收件夾。還沒有人看過報告的工作項目，由「可使用 agent」的
  成員在報告下面按「請求合併」。你自己開的、不屬於主題的 session 的 worktree，要在手寫 code 模式把「檢視的工作區」切到
  那個 worktree，再按「請主人合併」（只有這個 worktree 的擁有者有這個按鈕）。主人讀過完整的 diff，再選
  「合併到主工作區」或「拒絕」（被拒絕的 worktree 保持原狀，原因會顯示出來）。
- **合併和主工作區有衝突時**，合併會停下來，主工作區不變。主人或「可使用 agent」的成員可以選
  「請 agent 解決衝突」：smurg 把主工作區的變更帶進這個項目的 worktree，項目的 agent 解決有衝突的地方、寫出新版本的
  報告。這份報告要再看過一次，之後變更才會回到主人的收件夾。
- 結束一個不屬於主題、在 worktree 裡工作的 agent session 時，會問你要不要保留它的 worktree；刪除它會連同還沒合併的修改
  一起刪除，無法復原。

## 8.「主人已離線」是什麼意思

主人的 `smurg host` 沒有在執行、主人的電腦進入睡眠（例如闔上筆電螢幕），或主人的網路斷了。主人一離線，所有人在 10 秒內
就會看到「主人已離線」。

- 所有東西都在主人的電腦上，所以在主人回來之前，**檔案修改不會被儲存，不能傳任何東西給 agent，也不能投票和回答**。
  所有內容仍然讀得到。在等人處理的 agent 會在主人的電腦上繼續等。
- 主人回來後會**自動重新連線**，不用重新整理。離線期間你在編輯器打的字不會丟掉，會在重新連上後送出。只有一種情況要你
  決定：主人的電腦重新載入了這個檔案（例如主人的 smurg 重新啟動過），而且內容和你的版本不同，無法自動合併。這時畫面會
  顯示「你有修改還沒存到主人電腦」，讓你選「用我的版本取代」「複製我的版本」或「捨棄我的版本」。
- 主人的電腦沒有睡眠、只是你自己斷線時，agent 會在主人電腦上繼續工作；重新連上後看得到發生過的所有事。
- 「主人已停止分享這個工作區」表示主人執行了 `smurg stop`：終端機 session 已經結束，agent session 則是暫停。主人重新
  開始分享後會自動重新連線。
- **主人的 smurg 重新啟動之後**，每一段對話都讀得到，每個 agent 都待命，但什麼都不會自己執行：計畫會暫停
  （「主人電腦上的 smurg 重新啟動了。」），要由主人或「可使用 agent」的成員按「全部繼續」。之前開著的選擇題，會在它的
  session 繼續時再問一次；還在等 agent 讀的訊息（「Claude 重新啟動後會讀到」）也會在那時送出。
- 「無法連上伺服器」是另一回事：那是你和 relay 之間的網路問題。

**smurg 更新的時候：和版本有關的畫面。** 你用的網頁來自 relay，每次 smurg 有新版本，relay 上的網頁就會換新；主人的 `smurg`
則由主人自己更新。兩邊必須使用同一個通訊協定版本，所以更新前後你可能會看到下面其中一個畫面。每個畫面都會說該由誰處理：

- 「這個分頁是更新之前開的」：你的分頁開著的時候 smurg 更新了，分頁裡還是更新前的網頁。請重新整理頁面。你還是成員，
  不需要新的邀請連結。
- 「主人的 smurg 比這個網頁舊」：你的網頁已經是最新的，主人還沒有更新。你能做的只有通知主人：請主人停止分享、執行
  `smurg update`，再重新分享（自己架設 relay 的主人還要重新部署 relay）。之後再重新整理頁面。
- 「版本不相容」：網頁正在確認是上面哪一種情況的那一下子，或是它問不到 relay 的時候，會顯示這個畫面。這時它會把兩個
  步驟都列出來：先重新整理；如果頁面還是這樣說，就是主人需要更新。
- 「smurg 已經更新」：出現在某一欄、某個面板，或佔滿整個頁面，旁邊有「重新整理頁面」按鈕。你的分頁還沒載入的那部分
  網頁，已經被更新換掉了。請重新整理；如果主人還沒更新，頁面到時會告訴你。
- 「這個瀏覽器的 smurg 金鑰是比較新的網頁寫的」：這個瀏覽器已經用過比較新的 smurg 網頁，而這個分頁是比較舊的。沒有任何
  東西被更動。請重新整理頁面，換成比較新的網頁。

如果你是用邀請連結加入到一半時看到這些畫面，一樣重新整理就好：網頁會留著那個連結，再問你一次「要加入這個工作區嗎？」。
只有封鎖網站資料的瀏覽器留不住連結，這時請再開一次邀請連結。

主人更新 smurg 之後，工作區會保留下來：成員、角色和裝置都會沿用，從 0.4.0 更新也一樣。你不用重新加入，也不會被問主人的
金鑰。如果主人更新之後你的網頁顯示「安全警告：已拒絕連線」，或是打開連結時被問「主人的電腦金鑰和之前不同」，請照 §1 的
方法向主人核對指紋，並請主人給你連結：從 0.4.0 更新到 0.5.0 的主人可能不得不重新建立工作區，之後也可能已經換回原來的
那一個。從 0.5.0 開始，各個角色能做的事比 0.4.0 多，你擁有的是
原來那個角色現在的權限（§2）。

## 9. 離開工作區：會結束什麼

右上角的「**離開**」→ 確認「離開」。

**會結束**（幾秒內）：你開的終端機 session，以及你開的、不屬於任何主題的 agent session。這些 session 的 worktree 會連同
裡面的修改保留下來，而且仍然是你的：你再打開工作區時還找得到它們。

**會轉給主人**：你建立或開始的主題的 session。它們會繼續執行，改由主人照顧，所以計畫不會因為你離開而停下來。原本該由你
決定的選擇題，改由下一個人或主人決定。

**會跟著你一起移除**：你在還開著的選擇題上的投票、你傳出去而 agent 還沒讀到的訊息、你設為一律允許的指令類型，以及你
放寬過的權限模式。你開始但還沒開工的工作項目，要等有人重新開始才會開始。

**不會被刪除**：

- 你的**成員資格**：主人的成員清單裡仍然有你，你之後可以用同一個瀏覽器重新打開工作區。要完全移除你，得由主人踢出。
- 你在分享資料夾裡改過、新增的檔案，以及主題資料夾裡的所有東西：它們是主人專案的一部分。
- 你參與過的對話、活動動態和主人電腦上的操作紀錄。

**只是關掉分頁或斷線**不算離開：什麼都不會結束，等你處理的事會繼續等（過一陣子，主人和「可使用 agent」的成員可以代你
回答）。

主人把你的角色改成不能再使用 agent 時，同樣的東西會結束、轉給主人、被移除（你還能投票的話，投票會留著），你保留下來的
worktree 也會轉給主人：你不能再移除它們。主人把你移出工作區時也一樣，而且你開始的主題 session 在轉給主人之前還會先被
停止，你提出而還沒有人決定的建議也會被關閉。

## 10. 用終端機（CLI）加入（選用）

`smurg` 指令可以把工作區裡的**終端機 session** 接到你自己電腦的終端機（macOS 或 Linux）。agent session 是對話，只能在
瀏覽器裡開啟；這個指令會把它們列出來。先用一行指令安裝（和主人用的是同一個程式；詳見[主人指南](HOSTING.md) §1）：

```sh
curl -fsSL https://smurg.ai/install.sh | sh
```

然後加入：

```sh
smurg attach --invite -       # 執行後貼上邀請連結，按 Enter（不會顯示在畫面上）
```

smurg 會連到邀請連結上的網站（relay），不需要 `--relay`。這台電腦還沒登入那個 relay 時，它會先請你登入：終端機印出
一個網址（`https://app.smurg.ai/device`）和一組代碼。在任何裝置（電腦或手機）的瀏覽器打開網址、用 Google 帳號登入、
輸入代碼，確認頁上的帳號是你的之後按「允許」。**只有你自己剛在終端機執行 smurg 時才按「允許」；如果是別人給你的代碼，
請按「拒絕」。**

- **請用 `--invite -`**（或環境變數 `SMURG_INVITE`）。直接寫 `smurg attach --invite https://…#k=…&s=…` 也可以，但連結裡的
  密鑰會留在 shell 的歷史紀錄，執行期間也會出現在其他使用者看得到的程序列表（`ps`）裡。
- 終端機是一個新的裝置，**第一次**需要邀請連結。瀏覽器用過的連結如果已經用完或過期，請主人給你一個**和你目前角色相同**的
  新連結（不同角色的連結不能用）。之後用 `smurg attach --workspace <工作區代碼>`（只加入過一個工作區時不用指定）。
- 少數環境的網頁和 relay 網址不同（例如開發環境）。如果 smurg 說你登入過另一個網址、還沒有登入邀請連結的
  網址，照它的提示加上 `--relay <relay 網址>`（主人會告訴你）。
- 需要登入時，有桌面的電腦上 smurg 也會自動打開那個網址；在 SSH、腳本或沒有終端機的情況下不會（也可以用
  `--no-browser`），用你面前的電腦或手機打開就好，透過 SSH 也不需要其他設定。
- 主人換了工作區的金鑰之後（§1「要不要核對金鑰指紋」），`smurg attach --workspace …` 會停下來，說主人電腦的金鑰和上次記錄
  的不同。向主人確認過之後，用主人給的新連結執行 `smurg attach --invite -`：smurg 會印出「主人的電腦金鑰和之前不同」、
  上次記錄的和邀請連結的金鑰指紋，問你要不要繼續。邀請連結的指紋和主人用 `smurg status` 看到的一樣，才輸入 `y`；其他輸入
  會取消，什麼都不會送出。不在終端機裡執行（例如腳本）時不會問，確認過之後加上 `--accept-new-key`。如果你的角色和
  連結的角色不一樣（主人給組員的連結通常是「可編輯」的連結），smurg 接著會說
  「邀請連結無效、已過期或已用完，請向主人索取新的連結。」新的金鑰其實已經記下來了：再執行一次
  `smurg attach --workspace …` 就好。
- **你的 `smurg` 和主人的版本不同時**，`smurg attach` 連不上，並且會說該由哪一邊處理。它會向 smurg 的下載站查詢最新的
  版本。有比你新的版本時：「已經有更新的版本（0.5.1）：請更新這個 smurg（smurg update），再重新連線。」你的已經是最新
  版本時，它會說主人的 smurg 比較舊：「請主人停止分享、執行 smurg update，再重新分享；然後你再重新連線。」查不到的時候，
  它會把兩個步驟都列出來，先列你自己的：
  「這個 smurg 和主人的 smurg 版本不同，無法連線。請先在這台電腦執行 smurg update；如果它說已經是最新版本，就是主人的 smurg 比較舊：請主人停止分享、執行 smurg update，再重新分享。」
  `smurg update` 會保留這台電腦的裝置金鑰和你加入過的工作區：更新之後不需要新的邀請連結。

加入之後：

```sh
smurg attach                  # 先列出終端機 session（編號、擁有者、狀態），再列出 agent session 和它們的主題與狀態
smurg attach 2                # 把 2 號終端機 session 接到這個終端機；按 Ctrl-] 離開（session 繼續執行）
```

在終端機的清單下面，會列出 agent session（「agent session（對話）：」）和它們的狀態與主題，以及在瀏覽器裡開啟它們的
網址。把 agent session 指定給 `smurg attach`，只會印出它是對話、不是終端機。

主人和「可使用 agent」的成員可以在任何終端機 session 裡輸入；其他角色只能看（會先顯示
「唯讀模式」）。主人離線時，`smurg attach` 幾秒內就會告訴你。為了保護你的終端機，session 的輸出在顯示前會過濾：終端機
查詢、剪貼簿存取（OSC 52）和其他不認得的控制序列都不會送到你的終端機（別人 session 裡的程式可能被誘導輸出這些序列）。

CLI 不能開 session、不能傳訊息給 agent、不能投票、不能提出建議，也沒有「離開」：這些請用網頁。
