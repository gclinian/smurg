開放原始碼 · MIT macOS 與 Linux

架在你自己電腦上的即時工作區，讓組員和 Claude Code 一起工作。

用 smurg host 分享一個專案資料夾。團隊和一個 agent 討論一個主題，agent 會出選擇題讓大家決定，再寫出 spec 和計畫；每個工作項目由一個 agent 完成，最後由人閱讀每一份結果報告。這一切都在你的電腦上執行，中間的 relay 只轉送端對端加密後的資料。

在要分享資料夾的電腦上安裝

curl -fsSL https://smurg.ai/install.sh | sh

支援 macOS（Apple silicon、Intel）與 Linux（x64、arm64，glibc）。安裝程式從 downloads.smurg.ai 下載單一執行檔，只在 sha256 與這個版本的 SHA256SUMS 相符時，才安裝到 ~/.local/bin/smurg。不需要 Node.js。

收到邀請連結了嗎？用 Chrome 打開就好，不需要安裝任何東西。

01

怎麼運作

一個人當主人，其他人用連結加入。資料夾、agent 和它們的對話，都留在主人的電腦上。

  1. 步驟 1

    主人分享資料夾

    先用 Google 帳號登入，再分享資料夾。smurg 在前景執行，會印出兩個連結：你自己的連結（以主人身分打開工作區，不要給別人），以及給組員的邀請連結（預設角色「可編輯」，7 天內有效）。按 Ctrl-C 停止分享。

    smurg login
smurg host ~/projects/my-app

  2. 步驟 2

    組員加入

    用私訊傳送邀請連結：# 之後的部分就是密鑰。組員用 Chrome 打開連結、用 Google 登入、按「加入」，不需要安裝任何東西。每個人都有自己的收件夾，放著等他處理的事：一張還沒投的票、一題要他決定的選擇題、一份待看的報告。

    https://app.smurg.ai/join/<id>#…

  3. 步驟 3

    討論、計畫、實作、檢視

    為一個功能或一件工作開一個主題。大家和同一個 agent 對話：它出選擇題，團隊投票，再由負責的人送出答案。agent 寫出 spec 和一份由工作項目組成的計畫；每個項目由一個 agent 在自己的 git worktree 裡完成，執行指令之前會先問。每個完成的項目都有結果報告，由人讀過並標記為已看過，最後由主人合併。

02

能做什麼

  • 一起決定

    agent 把需要決定的事用選擇題交給團隊。除了「旁觀」，每個人都可以投票和留言，即時看到彼此的選擇；最後由一個人，也就是這個 session 的負責人，送出答案。agent 收到的是答案和投票結果，不會收到留言，除非送出答案的人把某一則留言加進給 agent 的備註。

  • spec 和計畫都是檔案

    每個主題在專案裡有一份 SPEC.md 和一份 PLAN.md，用 git 記錄版本。它們由 agent 寫出來；大家可以在瀏覽器裡一起編輯，或請 agent 修改。計畫是一份工作項目的清單，agent 會建議每個項目由誰照顧。

  • 每個工作項目一個 agent

    按下開始後，每個工作項目開一個 Claude Code session，各自在自己的 git worktree 裡。agent 在裡面改檔案不用先問，執行指令之前會先問；「可使用 agent」的組員可以只允許一次，或一律允許那一類指令。停下來的工作會進到某個人的收件夾，不會沒有人知道。

  • 可以檢視的結果報告

    完成的項目附有一份報告：做了什麼、為什麼這樣做、怎麼驗證的、要注意什麼，以及 diff。可以追問，然後標記為已看過。看過的變更會等主人處理：主人讀過完整的 diff 再合併；有衝突時交回給這個項目的 agent。

  • 收件夾，以及並排的欄

    收件夾放的是等你處理的事：要你決定的選擇題、還沒投的票、權限請求、建議、報告、提及。事情處理完，項目就會離開。最多可以並排四欄：對話、spec、計畫、報告。

  • 在手寫 code 模式一起編輯

    切換開關的另一邊：檔案樹和好幾個人可以同時打字的共用編輯器、上傳與下載、一般的終端機，以及活動動態。你在檔案裡開始打字後，agent 就不能修改它，直到你停下來；外部的修改和你正在打的內容重疊時，保留你打的內容，另一個版本放進衝突面板。

  • 角色與主人控制台

    邀請時可以選「旁觀」「可編輯」或「可使用 agent」。「旁觀」只能看；「可編輯」可以編輯、投票，並提出要有人採用才會送給 agent 的建議；「可使用 agent」的組員可以傳訊息給 agent、允許指令，都是以主人的身分。主人控制台列出成員、角色、邀請連結、session、設定和操作紀錄。主人的電腦睡眠時，所有人幾秒內就會看到。

03

安全模型，白話說明

你的程式碼只會以加密後的形式經過 smurg 的 relay。以下說明這代表什麼，以及它做不到的地方。

端對端加密

每個瀏覽器和終端機都和主人的電腦各自建立一條加密通道（Noise 協定）。邀請連結 # 之後的部分帶著主人電腦金鑰的指紋和一組密鑰，瀏覽器不會把這一段送到任何伺服器。relay 想冒充主人時，連線會被拒絕。

所有東西都留在主人的電腦上

檔案、agent、它們的對話和操作紀錄都在主人的電腦上，relay 不保存其中任何一樣。主人的電腦睡眠或 smurg 停止時，沒有人能使用工作區；主人回來後會自動重新連線。smurg 本身重新啟動之後，什麼都不會自己執行：執行到一半的計畫會等主人或「可使用 agent」的組員讓它繼續。

agent 以主人的身分執行

每個 agent 和終端機都在主人的電腦上、以主人的身分執行：用主人的帳號、檔案和 Claude Code 登入，沒有沙盒。除了主人，只有「可使用 agent」的組員能傳訊息給 agent、允許它請求執行的事，或開終端機；「可編輯」的組員提出建議，「旁觀」的組員只能看。拿到這個角色的人可以在你的電腦上執行任何指令、讀你的家目錄、用你的 Claude 帳號，所以只給你完全信任的人。

agent 自己能做什麼

agent 每一次使用工具，smurg 都會自己先檢查，在 Claude Code 自己的權限機制之前。主題的討論 agent 只能讀專案、寫 spec 和計畫：沒有 shell，也沒有網路。工作項目的 agent 只在自己的 worktree 裡改檔案，執行指令前會先問。smurg 沒有在執行時，agent 下一次使用工具會被拒絕。

沒有東西會在沒人看過的情況下送給 agent

「可編輯」的組員傳的訊息是建議：要有「可使用 agent」的人採用，agent 才會收到，而且收到的就是畫面上顯示的那段文字。工作項目只會從這樣的人確認過的 spec 和計畫開始；之後只要其中一個檔案變了，項目就不會開始，要等這樣的人再按一次開始。

relay 看得到什麼

每條連線是哪個 Google 帳號（帳號 ID、名稱、大頭貼；登入時 Google 也會給 relay 帳號的 email，只有帳號沒有名稱時拿來當顯示名稱）、從哪個 IP 位址連線、連到哪個工作區代碼，以及每筆資料的大小和時間，所以看得出誰和誰在什麼時候一起工作。看不到檔案內容、檔名、對話、終端機畫面、指令、邀請連結的密鑰或任何金鑰。它只保存每個工作區的代碼和主人是哪個帳號。使用公用 relay 時，架設它的 smurg 維護者和 Cloudflare 也看得到同樣的內容。

smurg 防不了的事

  • 工作區裡的每個人都看得到分享資料夾裡的每個檔案，包括 .env；只有 .git、.envrc、smurg 自己的 .smurg 資料夾和主人個人的 Claude Code 設定看不到。不要分享放了密碼、金鑰或個人資料的資料夾。
  • 每個人都讀得到和 agent 的每一段對話，之後才加入的人也一樣；agent 讀到的任何東西，它都可能說出來。smurg 會遮蔽看起來像常見金鑰的文字，但這只是盡力而為。
  • agent 會讀到組員寫的內容：程式碼、spec、計畫。檔案裡可能藏著要 agent 執行的指示（prompt injection）。允許指令之前先讀過；設定一律允許某一類指令之前，請多想一下。
  • 「可使用 agent」的組員在你的電腦上能做你能做的任何事：執行任何指令、讀你的家目錄、用掉你的 Claude 額度。smurg 無法限制這些事。你自己的 Claude Code 設定已經允許的規則，對這裡的 agent 也有效；smurg 會告訴你一次是哪些。
  • 每個 agent 都用主人的 Claude 帳號，替組員工作時也一樣。Anthropic 的條款不允許把個人訂閱提供給其他人使用；要和一群人分享的主人，應該讓 Claude Code 改用給團隊使用的帳號登入。
  • 網頁版由 relay 提供。和所有在瀏覽器裡做的端對端加密一樣，被竄改的網頁可能洩漏金鑰；CLI 沒有這個問題。

分享之前，請先讀主人指南

04

支援的平台與需求

主人的電腦
macOS 11 以上（Apple silicon 或 Intel）；Linux 需要 glibc 2.28 以上（Ubuntu 20.04 以上），x64 或 arm64。不支援 Windows 主人，也不支援 musl 的 Linux（例如 Alpine）。
Claude Code
要執行 agent，主人的電腦需要已經登入的 Claude Code（claude 指令）2.1.288 以上：每個 agent 都用主人的登入。要執行工作項目還需要 git，分享的資料夾也必須是 git 儲存庫。
組員
任何有瀏覽器的作業系統都可以。目前測試過的是電腦上的 Chrome，Safari 和 Firefox 還沒測試過。也可以在 macOS 或 Linux 上用 smurg CLI。
登入
Google 帳號，主人和組員都一樣。
語言
英文與繁體中文：網頁版、smurg 指令和使用說明都有。每個人看到的是自己的語言，在同一個工作區裡也一樣。
relay
公用 relay 使用 Cloudflare 的免費方案，請合理使用：所有人共用每天的用量上限，用完時到台灣時間早上 8 點（UTC 0 點）之前，所有人都無法連線。relay 也是開放原始碼：你可以用自己的 Cloudflare 帳號自己架設 relay。

smurg 目前是原型。開發和測試都在 Apple silicon 的 macOS 上進行；Intel Mac 與 Linux 的執行檔由 GitHub Actions 建置並跑冒煙測試，還沒有人真的在 Linux 上當過主人。從討論到看過結果的流程，是用照劇本回應的模型替身測試的，沒有用真正的 Claude 帳號，所以真正的模型在這個流程裡的表現可能還需要調整。每個版本的變更列在變更紀錄裡。

07

常見問題

需要安裝 Node.js 嗎？

不需要。安裝程式會下載為你的電腦建置的單一執行檔，安裝它不需要 sudo。用瀏覽器加入的組員不需要安裝任何東西。

macOS 的執行檔只有 ad-hoc 簽章，沒有 Apple 的開發者簽章（Developer ID）。請用上面那行指令安裝：安裝程式驗證 sha256 之後，會移除 quarantine 標記。用瀏覽器下載的執行檔會被 Gatekeeper 擋下。

怎麼更新或移除？

smurg update 會把執行檔換成最新版本，一樣先驗證 sha256（請先停止分享）。smurg uninstall 先列出要移除的東西，再移除執行檔、快取和 ~/.smurg；專案資料夾裡的 .smurg/ 不會動，留給你自己決定。

relay 看得到什麼？

每條連線的 Google 帳號（帳號 ID、名稱、大頭貼；登入時還有 email）和 IP 位址、工作區代碼，以及每筆資料的大小和時間，所以看得出誰和誰在什麼時候一起工作。檔案、檔名、終端機畫面、指令和金鑰，都在主人的電腦和每位組員之間端對端加密。如果一個專案連這些都不能讓公用 relay 知道，就自己架設 relay：這時看得到這些的只有你和你的 Cloudflare 帳號。

組員需要自己的 Claude 帳號嗎？

不需要。每個 agent 都在主人的電腦上、用主人的 Claude Code 登入執行，用量算在主人的帳號上。「旁觀」的組員只能看，「可編輯」的組員可以投票和提出建議，「可使用 agent」的組員可以傳訊息給 agent、允許指令，全都是以主人的身分。主人的電腦要裝好 Claude Code 並登入。Anthropic 的條款不允許把個人訂閱提供給其他人使用，所以要和一群人分享的主人應該用給團隊使用的帳號；主人指南有更多說明。

agent 不用先問就能做什麼？

主題的討論 agent 只能讀專案，並且只能寫這個主題的 spec 和計畫。工作項目的 agent 在自己的 worktree 裡改檔案、執行唯讀的指令和簡單的檔案指令（列出、複製或搬移檔案）；其他的事它都會先問（已經設為一律允許的那一類指令除外），只有主人或「可使用 agent」的組員可以允許。這些是 smurg 自己在 agent 每一次使用工具之前檢查的。主人要知道一個例外：你自己的 Claude Code 設定已經允許的指令，在這裡也不會先問。

這套流程用真正的 Claude 測試過嗎？

開發者沒有。整個流程是用照劇本回應的模型替身測試的，真正的 Claude Code 也只在 Mac 上對著假的 API 執行過；沒有使用任何真正的 Claude 帳號。所以真正的模型會不會用卡片提出選擇題、會不會用 smurg 檢查的格式寫計畫和報告，都還沒有驗證。smurg 會自己檢查這些格式、請 agent 修正，並把停下來的工作放進收件夾。

看得到原始碼嗎？

看得到。smurg 是開放原始碼軟體，以 MIT 授權條款釋出，原始碼在 GitHub。smurg 用到的其他專案的元件，依它們各自的授權條款提供，列在執行檔的第三方授權聲明和網頁版的第三方授權聲明。

可以自己架設 relay 嗎？

可以。relay 是一個 Cloudflare Worker：照著 relay 的說明文件（英文），用自己的 Cloudflare 帳號（免費方案即可）和自己的 Google OAuth client 部署，再用 smurg login --relay 加上你的 relay 的網址登入。之後你印出的邀請連結會指向你的 relay，它也有自己的每日用量。

支援哪些瀏覽器？

測試過的是電腦上的 Chrome。Safari 和 Firefox 還沒測試過。

主人的電腦睡眠時會怎樣？

所有人幾秒內就會看到「主人已離線」。編輯的內容會留在瀏覽器裡，主人回來後再送出；這段期間碰不到 agent，在等人處理的 agent 會繼續等。分享期間 smurg 會防止電腦閒置時睡眠，但闔上筆電螢幕仍然會睡眠。smurg 本身重新啟動之後，每一段對話都還在，而且什麼都不會自己執行：執行到一半的計畫會等主人或「可使用 agent」的組員讓它繼續。
