Open source · MIT macOS and Linux

A real-time workspace for your team and Claude Code, hosted on your own computer.

Share a project folder with smurg host. Your team discusses a topic with an agent that asks multiple-choice questions; the agent writes a spec and a plan; one agent per work item does the work; people read each result report. It all runs on your machine, and the relay in between only forwards end-to-end encrypted data.

Install on the computer that shares the folder

curl -fsSL https://smurg.ai/install.sh | sh

For macOS (Apple silicon, Intel) and Linux (x64, arm64, glibc). The script downloads one executable from downloads.smurg.ai and installs it to ~/.local/bin/smurg only if its SHA-256 matches the release’s SHA256SUMS. No Node.js needed.

Got an invite link? Open it in Chrome; there is nothing to install.

01

How it works

One person hosts. Everyone else joins with a link. The folder, the agents and their conversations stay on the host’s computer.

  1. Step 1

    The host shares a folder

    Log in with Google, then share a folder. smurg runs in the foreground and prints two links: your own, which opens the workspace as the host, and an invite link for teammates (Editor role by default, valid for 7 days). Ctrl-C stops sharing.

    smurg login
smurg host ~/projects/my-app

  2. Step 2

    Teammates join

    Send the invite link in a private message: the part after # is the key. Teammates open it in Chrome, log in with Google and join, with nothing to install. Each of them gets an inbox with what waits for them: a vote, a question to decide, a report to review.

    https://app.smurg.ai/join/<id>#…

  3. Step 3

    Discuss, plan, build, review

    Start a topic for a feature or a task. Everyone talks with one agent: it asks multiple-choice questions, the team votes, and the person responsible submits the answer. The agent writes a spec and a plan of work items; one agent per item does the work in its own git worktree and asks before it runs a command. Each finished item has a result report that someone reads and marks as reviewed; then the host merges.

02

What you can do

  • Decide together

    An agent brings its decisions to the team as multiple-choice questions. Everyone but Viewers votes and comments, seeing each other’s choices live; one person, the one responsible for the session, submits the answer. The agent gets the answer and the vote, never the comments.

  • A spec and a plan, as files

    Each topic has a SPEC.md and a PLAN.md in the project, versioned with git. The agent writes them; people edit them together in the browser or ask the agent to revise. The plan is a list of work items, and the agent suggests who looks after which one.

  • One agent per work item

    Start opens one Claude Code session per work item, each in its own git worktree. An agent edits there without asking and asks before it runs a command; a teammate with agent access allows it once, or always for that kind of command. Work that stops reaches someone’s inbox instead of stopping unseen.

  • Result reports you can review

    A finished item comes with a report: what was done, why, how it was verified, what to watch out for, and the diff. Ask a follow-up, then mark it as reviewed. The reviewed change waits for the host, who reads the full diff and merges; a conflict goes back to the item’s agent.

  • An inbox, and columns side by side

    Your inbox holds what waits for you: questions to decide, open votes, permission requests, suggestions, reports, mentions. An item leaves when the thing is settled. Up to four columns stand side by side: conversations, a spec, a plan, a report.

  • Edit together in code mode

    Behind a switch: a file tree and a shared editor where several people type at once, uploads and downloads, plain terminals, and an activity feed. Once you type in a file, agents can’t change it until you pause; where an outside change overlaps your typing, your text is kept and the other version goes to a conflicts panel.

  • Roles and a host console

    Invite people as Viewer, Editor or with Agent access. Viewers watch; Editors edit, vote and send suggestions that reach an agent only when accepted; teammates with agent access message agents and allow commands, as the host. The host console lists members, roles, invite links, sessions, settings and the audit log. If the host’s computer sleeps, everyone sees it within seconds.

03

Security, in plain words

Your code passes through smurg’s relay only in encrypted form. This is what that means, and where it stops.

End-to-end encrypted

Every browser and terminal opens its own encrypted channel to the host’s computer, using the Noise protocol. The invite link carries the fingerprint of the host’s key and a secret after the #, the part of a link that browsers never send to a server. A relay that tries to pose as the host is refused.

The host keeps everything

Files, agents, their conversations and the audit log live on the host’s computer; the relay stores none of them. While that computer sleeps or smurg is stopped, nobody can use the workspace; it reconnects when the host is back, and nothing runs again until someone continues it.

Agents run as the host

Every agent and terminal runs on the host’s computer as the host: the host’s account, files and Claude Code login, with no sandbox. Besides the host, only teammates with the Agent access role message agents, allow what they ask to run, or open a terminal; Editors send suggestions and Viewers watch. That role lets someone run any command on your computer, read your home folder and use your Claude account, so give it only to people you fully trust.

What an agent may do by itself

smurg checks every tool call of an agent itself, before Claude Code’s own permissions. A topic’s discussion agent reads the project and writes only the spec and the plan: no shell, no network. A work item’s agent edits inside its own worktree and asks before commands. If smurg is not running, an agent’s next tool call is refused.

Nothing reaches an agent unseen

An Editor’s message is a suggestion: an agent gets it only when someone with agent access accepts it, as exactly the text that was shown. Work items start only from the spec and the plan that such a person confirmed; if either file changed since, the item waits.

What the relay sees

Which Google account each connection belongs to (its ID, name and picture; at login Google also gives the relay the account’s email, used as the display name only when the account has no name), its IP address, the workspace code, and the size and time of each message, so it can tell who worked with whom, and when. Not file contents, file names, conversations, terminal output, commands, the invite secret or any key. It keeps only each workspace’s code and its owner’s account. On the shared relay, smurg’s maintainer, who runs it, and Cloudflare can see the same.

What smurg can’t protect you from

  • Everyone in a workspace can read every file in the shared folder, .env files included; only .git, .envrc, smurg’s own .smurg folder and the host’s personal Claude Code settings are hidden. Don’t share a folder that holds passwords, keys or personal data.
  • Everyone can read every conversation with an agent, including people who join later, and whatever an agent reads it may repeat. smurg masks text that looks like a well-known kind of key, but that is best effort.
  • Agents read what teammates write: the code, the spec, the plan. A file could hide instructions meant for them (prompt injection). Read a command before you allow it, and think twice before you always allow a kind of command.
  • A teammate with agent access can do on your computer whatever you can: run any command, read your home folder, spend your Claude usage. smurg can’t limit that. The rules your own Claude Code settings already allow apply to agents here too; smurg tells you once which.
  • Every agent uses the host’s Claude account, also when it works for a teammate. Anthropic’s terms don’t allow making a personal subscription available to other people; a host who shares with a group should log Claude Code in with an account meant for teams.
  • The web app is served by the relay. As with any end-to-end encryption in a browser, a tampered app could leak keys; the CLI doesn’t have this problem.

04

Platforms and requirements

Host computer
macOS 11 or later on Apple silicon or Intel. Linux with glibc 2.28 or later (Ubuntu 20.04 and later) on x64 or arm64. Windows hosts and musl-based Linux such as Alpine are not supported.
Claude Code
To run agents, the host’s computer needs Claude Code (the claude command) 2.1.288 or later, logged in: every agent uses the host’s login. Carrying out work items also needs git, and the shared folder must be a git repository.
Teammates
Any operating system with a browser. Chrome on a computer is the tested one; Safari and Firefox have not been tested yet. Optionally the smurg CLI on macOS or Linux.
Login
A Google account, for the host and for teammates.
Languages
English and Traditional Chinese, in the web app, the smurg command and the guides. Everyone sees their own language, also inside one workspace.
Relay
The shared relay runs on Cloudflare’s free plan and is for fair use: everyone shares one daily quota, and when it runs out nobody can connect until 00:00 UTC (08:00 in Taiwan). The relay is open source too: you can run your own relay on your own Cloudflare account.

smurg is a prototype. It is developed and tested on macOS on Apple silicon; the Intel Mac and Linux builds are built and smoke-tested on GitHub Actions, and nobody has hosted on Linux for real yet. The flow from discussion to reviewed result was tested with a scripted stand-in for the model, not with a real Claude account, so how a real model behaves in it may still need tuning. What changed in each version is in the changelog.

07

Questions

Do I need Node.js?

No. The installer downloads a single executable built for your computer; installing it needs no sudo. Teammates who join in a browser install nothing.

The macOS executable has only an ad-hoc signature, not an Apple Developer ID. Install it with the line above: after checking the SHA-256, the installer removes the quarantine flag. A copy downloaded with a browser is blocked by Gatekeeper.

How do I update or remove it?

smurg update replaces the executable with the newest version, after the same SHA-256 check (stop sharing first). smurg uninstall lists what it will remove, then removes the executable, its cache and ~/.smurg; the .smurg/ folders inside your projects are left to you.

What does the relay see?

The Google account of each connection (ID, name and picture; at login also the email), its IP address, the workspace code, and the size and time of each message, so it can tell who worked with whom, and when. Files, file names, terminal output, commands and keys are end-to-end encrypted between the host’s computer and each teammate. If what the shared relay sees is too much for a project, run your own relay: then only you and your Cloudflare account see it.

Do teammates need their own Claude account?

No. Every agent runs on the host’s computer with the host’s Claude Code login, so its usage counts against the host’s account. Viewers watch, Editors vote and send suggestions, and teammates with agent access message agents and allow commands, all as the host. The host needs Claude Code installed and logged in. Anthropic’s terms don’t allow making a personal subscription available to other people, so a host who shares with a group should use an account meant for teams; the host guide says more.

What can an agent do without asking?

A topic’s discussion agent reads the project and writes only the topic’s spec and plan. A work item’s agent edits files in its own worktree and runs read-only commands there; for anything else it asks, and only the host or a teammate with agent access can allow it. smurg checks this itself before every tool call. One exception is yours to know as a host: commands that your own Claude Code settings already allow run without asking here too.

Has this been tested with real Claude?

Not by its developers. The whole flow was tested with a scripted stand-in for the model, and real Claude Code only against a fake API; no real Claude account was used. So whether a real model asks its questions as cards and writes the plan and the report in the format smurg checks is not verified yet. smurg checks those formats itself, asks the agent to fix them, and puts work that stopped into an inbox.

Can I see the source code?

Yes. smurg is open source under the MIT License, and the source code is on GitHub. The components smurg is built from keep their own licenses, listed in the third-party notices of the executables and in those of the web app.

Can I run my own relay?

Yes. The relay is a Cloudflare Worker: deploy it with your own Cloudflare account (the free plan is enough) and your own Google OAuth client, following the relay’s README, then log in with smurg login --relay and your relay’s address. Your invite links then point at your relay, and it has its own daily quota.

Which browsers work?

Chrome on a computer is the one tested. Safari and Firefox have not been tested yet.

What happens when the host’s computer sleeps?

Everyone sees “Host offline” within seconds. Edits wait in the browser and are sent when the host is back; agents can’t be reached in the meantime, and the ones waiting for a person keep waiting. smurg keeps an idle computer awake while sharing, but closing a laptop’s lid still puts it to sleep. After smurg itself was restarted, every conversation is still there, and nothing runs until the host or a teammate with agent access continues it.
