Open source · MIT macOS and Linux

A real-time workspace for your team and Claude Code, hosted on your own computer.

Share a project folder with smurg host. In the browser, your team plans a feature with a Claude Code agent, agents build it, and people review each result. The relay in between only forwards end-to-end encrypted data.

Install on the computer that shares the folder

curl -fsSL https://smurg.ai/install.sh | sh

The script downloads one executable from downloads.smurg.ai and installs it to ~/.local/bin only if its SHA-256 matches the release’s SHA256SUMS. No Node.js needed.

Got an invite link? Open it in Chrome; there is nothing to install.

01

How it works

One person hosts; the others join with a link. The folder and the agents stay on the host’s computer.

  1. Step 1

    The host shares a folder

    Log in with Google and share a folder. smurg prints two links: your own (keep it to yourself) and an invite link for teammates.

    smurg login
smurg host ~/projects/my-app

  2. Step 2

    Teammates join

    Send the invite link in a private message: the part after # is the key. Teammates open it in Chrome and join, with nothing to install.

    https://app.smurg.ai/join/<id>#…

  3. Step 3

    Discuss, plan, build, review

    Start a topic. The team answers the agent’s questions, the agent writes a spec and a plan, one agent per work item builds it, and people review each result.

02

What you can do

  • Decide together

    An agent asks the team multiple-choice questions. People vote and see each other’s votes live; the person responsible submits the answer.

  • A spec and a plan, as files

    Each topic keeps a SPEC.md and a PLAN.md in the project. The agent writes them; people edit them together.

  • One agent per work item

    Each work item gets its own Claude Code session in its own git worktree. There it edits and runs simple file commands without asking, and asks before other commands.

  • Result reports you can review

    A finished item comes with a report: what was done, how it was verified, what to watch out for, and the diff. The host merges what was reviewed.

  • An inbox, and columns side by side

    Your inbox holds what waits for you. Up to four columns stand side by side: conversations, specs, plans and reports.

  • Edit together in code mode

    Behind a switch: a shared editor, the file tree and terminals. While you type in a file, agents can’t change it.

  • Roles and a host console

    Invite people as Viewer, Editor or with Agent access, and manage them in the host console. An Editor’s suggestion reaches an agent only once someone with Agent access accepts it.

03

Security, in plain words

Files, agents and conversations stay on the host’s computer. The relay only forwards encrypted data. Here is what that covers, and what it doesn’t.

End-to-end encrypted

Each channel uses the Noise protocol. The invite link carries the host’s key fingerprint and a secret after the #, the part browsers never send to a server, so a relay can’t pose as the host.

Agents run as the host

Agents and terminals run on the host’s computer as the host, with no sandbox. The Agent access role lets a teammate run any command on your computer, read your home folder and use your Claude account, so give it only to people you fully trust.

What an agent may do by itself

smurg checks every tool call itself. A topic’s discussion agent writes only the spec and the plan; a work item’s agent edits inside its own worktree and asks before commands.

What the relay sees

Each connection’s Google account and IP address, the workspace code, and the size and time of each message: enough to tell who worked with whom, and when. Never file contents, file names, conversations, commands or keys. On the shared relay, its maintainer and Cloudflare see the same.

What smurg can’t protect you from

  • Everyone in a workspace can read the files in the shared folder, .env files included. Don’t share a folder that holds passwords, keys or personal data.
  • Everyone can read every conversation with an agent, also people who join later, and an agent may repeat whatever it reads.
  • Agents read what teammates write, the spec and the plan included, and a file can hide instructions for them (prompt injection). Read a command before you allow it, and think twice before you always allow a kind of command.
  • Commands your own Claude Code settings already allow run here without asking too.
  • Every agent uses the host’s Claude account. Anthropic’s terms don’t allow making a personal subscription available to other people: for a group, log Claude Code in with an account meant for teams.
  • The relay serves the web app: as with any end-to-end encryption in a browser, a tampered app could leak keys. The CLI doesn’t have this problem.

Read the host guide before you share

04

Platforms and requirements

Host computer
macOS 11 or later (Apple silicon or Intel), or Linux with glibc 2.28 or later (x64 or arm64). Not Windows.
Claude Code
2.1.288 or later, logged in on the host’s computer. Work items also need git, in a folder that is a git repository.
Teammates
Any computer with Chrome; Safari and Firefox are untested. The smurg CLI is optional.
Login
A Google account, for the host and for teammates.
Languages
English and Traditional Chinese. Everyone sees their own.
Relay
The shared relay runs on Cloudflare’s free plan, with one daily quota for everyone: when it runs out, nobody can connect until 00:00 UTC. You can also run your own relay.

smurg is a prototype, developed on an Apple silicon Mac; the Intel Mac and Linux builds are only smoke-tested, and nobody has hosted on Linux for real yet. The flow was tested with a scripted stand-in for the model, not with a real Claude account. What changed is in the changelog.

07

Questions

Do I need Node.js?

No. The installer downloads a single executable and needs no sudo. The macOS executable has no Apple Developer ID: install it with the line above, which removes its quarantine flag after the SHA-256 check.

How do I update or remove it?

smurg update installs the newest version (stop sharing first). smurg uninstall removes the executable, its cache and ~/.smurg.

Do teammates need their own Claude account?

No. Every agent runs with the host’s Claude Code login, so its usage counts against the host’s account.

Has this been tested with real Claude?

Not by its developers: the flow was tested with a scripted stand-in for the model, and real Claude Code only against a fake API. How a real model fits the flow is not verified yet.

Can I see the source code?

Yes. smurg is open source under the MIT License, and the source is on GitHub. The components it is built from keep their own licenses: see the third-party notices of the executables and of the web app.

Can I run my own relay?

Yes. Deploy it to your own Cloudflare account (the free plan is enough), following the relay’s README, then log in with smurg login --relay and its address.

What happens when the host’s computer sleeps?

Everyone sees “Host offline” within seconds; edits wait in the browser until it is back. smurg keeps an idle computer awake while sharing, but closing a laptop’s lid still puts it to sleep.
